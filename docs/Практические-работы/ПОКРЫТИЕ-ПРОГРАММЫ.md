практических работ. Он служит картой курса и не является отдельным заданием.

## Общий цикл изменений, PR/MR и CI

Практическая работа № 1 завершается архитектурными наблюдениями. Начиная с
работы № 2 результаты накапливаются в одном личном репозитории тестов. Когда
работа создаёт или меняет файлы, используется следующий цикл:

1. создать рабочую ветку от актуальной `main`;
2. проверить `git diff` и сохранить связный коммит;
3. отправить один commit SHA в GitHub и GitLab;
4. открыть PR и MR в `main` личного репозитория;
5. добавить в описание ссылки на сценарии, тестовый код, отчёт и evidence;
6. сопоставить GitHub Actions и GitLab CI для одного SHA: событие, job, команду,
   итог, первую значимую ошибку и артефакты;
7. после исправления отправить новый коммит в оба remote и проверить запуски
   уже для нового SHA.

Если работа состоит только из наблюдения и файловых изменений не появилось,
результат остаётся в заметках без пустого коммита и формального PR/MR.

Jenkins используется там, где работа прямо включает Jenkins pipeline: № 2,
№ 14 и подготовленные межархитектурные профили. GitHub Actions и GitLab CI
сопоставляются при PR/MR, для которых настроен запуск. Состояние pipeline,
журналы и артефакты служат средством самопроверки выполненной работы.

## Границы результатов

Чек-листы в конце работ помогают проверить полноту собственного результата.
Они не задают процедуру оценивания преподавателем. Объём evidence выбирается по
ценности для воспроизведения и диагностики, а вывод ограничивается фактически
выполненными проверками, веткой, SHA, средой и тестовыми данными.
