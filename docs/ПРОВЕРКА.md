# Локальная проверка выпуска 1.0.0

Дата: 6 сентября 2026 года. Среда: Windows, Docker Engine 29.7.2 с Linux-контейнерами; тесты — Python 3.13.13, Pytest 8.3.5, Playwright 1.58.0 / Chromium. Приложение и PostgreSQL запускались в Docker, без обращения к удалённому учебному стенду и системной PostgreSQL.

В число проверок входят модульные тесты правил, оценщика, логов и схем, API и UI; для единой БД — ещё две проверки PostgreSQL. Межбазовые JOIN не имитируются в микросервисах. Ожидаемые падения buggy проверяются отдельным запуском; они не являются ошибкой готовности стенда.

Артефакты находятся в `artifacts/<каталог-прогона>` соответствующего рабочего дерева. Монолит fixed — корень проекта; остальные деревья созданы в `.worktrees/<архитектура>-<состояние>`. Сохранены JUnit XML, Allure-данные и логи. Эти каталоги не входят в Git и не появятся после клонирования; для новых доказательств запустите проверку на стенде.

Проверенные продуктовые коммиты закреплены в [releases/1.0.0.json](../releases/1.0.0.json). Общие материалы синхронизированы, постоянных веток продукта ровно шесть. Отдельный `student-work` содержит main и student/1–4; два стартовых теста показывают структуру, но не являются готовым решением заданий.

## Дополнительные проверки

- Матрица `verify_matrix.py`: каждый D01–D08 включён отдельно во всех трёх архитектурах, обнаружено 24 из 24 включений. На каждой архитектуре исправленный вариант пройден дважды, в том числе в обратном порядке тестов. Результаты — `artifacts/matrix/<архитектура>/verdict.json`. Это доверенные контрольные тесты с локальным браузером, не контейнерная приёмка студенческого кода.
- `verify_operations.py`: четыре одновременно работающие среды не разделяют пользователей и заявки; после перезапуска БД и приложения сохранились заявка, токен сессии и записи предыдущего запуска. Роли микросервисов не подключаются к чужой предметной БД. Остановка identity даёт 503, повторный запуск восстанавливает доступ, request_id найден в логах обоих сервисов. Доказательства — `artifacts/operations-5c52fa16d5`.
- Postman-коллекция выполнена Newman 6.2.2: 16 запросов, 32 проверки, ошибок нет. Артефакты — `artifacts/postman`.
- Locust 2.43.3: короткий прогон на 4 пользователях / 15 секунд, 60 запросов, ошибок нет. Артефакты — `artifacts/load/final*`. Это проверка работоспособности сценария, не измерение предельной производительности. Нулевой прогон дополнительно проверен: возвращает код 1, а не ложный успех.
- Очистка логов и артефактов проверена на искусственно состаренных файлах. Проверены сохранность новых файлов и отсутствие текста исключений с секретами в JSON-логах.
- Исправлено обрезание emoji браузерным maxlength; добавлены UI-проверки 80-символьного заголовка, 300-символьного комментария, 64-символьного пароля и международного email. Приведён в соответствие контракт PATCH: отсутствующее поле допустимо, явный null и пустой объект запрещены.
- Исправлена гонка вложенного Pytest при обходе общего Windows Temp: ограничен confcutdir. 24 параллельных повторных проверки наблюдателя прошли без ошибок.
- Сборка Vue/Vite выполнена. PowerShell-скрипты разобраны штатным парсером. Оба GitHub workflow проверены actionlint 1.7.12. `git diff --check` и аудит шести веток проходят.

## Что ещё требует проверки

Большой образ `mini-tickets-grader:1.0` намеренно не скачивался автоматически. Следовательно, фактический запуск студенческого кода в этом контейнере пока не подтверждён. Проверены правила оценивания модульными тестами, контрольная матрица с локальным браузером и корректный код 2 при отсутствии образа. Для завершения именно контейнерной приёмки выполните:

```powershell
.\scripts\Prepare-Lab.ps1 -Grader
.\.venv\Scripts\python.exe scripts/verify_grader.py --full
```

Вторая команда создаёт временные Git-работы: хорошие тесты, постоянное падение и пустой набор. Ожидается принятие только хорошей работы. Все результаты сохраняются в `artifacts/grader-self-test`.

GitHub, GitLab и Jenkins не подключались и репозитории не публиковались по договорённости с владельцем. CI-файлы и общий запускатель готовы, но настоящие PR/MR, webhook, права runner и публикацию обязательного статуса нужно проверить после подключения по [инструкции CI](CI.md). Проверка YAML не заменяет эти действия.

На удалённой машине ещё нужно подтвердить наличие Docker с Linux-контейнерами. Python 3.14 непосредственно на хосте, Firefox и WebKit в этой локальной приёмке не проверялись. Docker использует собственный Python 3.13. Allure-данные сформированы; HTML-просмотр требует дополнительного CLI или Jenkins-плагина.
