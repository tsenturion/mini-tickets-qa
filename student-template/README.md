# Работы по тестированию «Мини-заявок»

Это заготовка. Два примера подтверждают запуск, но не обнаруживают дефекты задания и не дают автоматический зачёт.

Для приватного продукта GitHub нужен secret `QA_PRODUCT_SSH_KEY` с отдельным
read-only deploy key. Он не даёт права менять продукт. Настраивает преподаватель;
приватный ключ нельзя добавлять в исходники. PR из fork не получает этот secret.

1. Создайте виртуальную среду, установите `requirements.txt`, выполните `python -m playwright install chromium`.
2. Задайте `BASE_URL`, например в PowerShell: `$env:BASE_URL='http://localhost:8101'`.
3. Запустите `python -m pytest --junitxml=artifacts/results.xml --alluredir=artifacts/allure --screenshot=only-on-failure --tracing=retain-on-failure`.
4. Работайте в `student/1`, `student/2`, `student/3` или `student/4`, затем отправьте PR/MR в `main` репозитория работ.

У каждого теста укажите `@pytest.mark.api` или `@pytest.mark.ui` и идентификатор `@pytest.mark.requirement('TICKET-01')` из требований преподавателя. Связь с требованием должна соответствовать содержанию теста. Не используйте прямой доступ к БД в переносимых API/UI-тестах модуля 8.

Данные создавайте уникальными. Новые заявки удаляйте в завершающей части фикстуры. Аккаунты и заявки, прошедшие жизненный цикл, окончательно удаляет запускатель временной среды. Общие исходные записи не изменяйте.

Исправленные версии должны пройти полностью. Пропуски, постоянные падения, ошибки настройки и тесты без проверок не дают зачёт. Нужны API и UI, включая отрицательные сценарии, полезная параметризация и Page Object. Ориентир: пять API- и два UI-теста на человека; оцениваются требования, а не количество строк.

Для GitHub преподаватель задаёт переменные `QA_PRODUCT_REPOSITORY` (владелец/репозиторий продукта) и `QA_PRODUCT_REF` (доверенный коммит). Для GitLab — `QA_PRODUCT_URL`, `QA_PRODUCT_REF`. После скачивания всех шести веток запускатель фиксирует их коммиты в `release-lock.json`.

Файлы CI здесь демонстрируют интеграцию. Вы можете изменять их в своей работе, поэтому они не защищают правила оценивания. Обязательный итоговый статус выдаётся из управляемого преподавателем задания Jenkins или другого доверенного pipeline. Подробности — в инструкции продукта `docs/CI.md`.
