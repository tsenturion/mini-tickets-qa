# Дополнительные упражнения по протоколам

Основной стенд использует JSON и Bearer-сессии. Следующие небольшие упражнения раскрывают другие способы взаимодействия, не увеличивая бизнес-приложение.

## HTTP Basic

Закодируйте строку `student:practice` в Base64 и соберите `Authorization: Basic ...`. Декодируйте обратно. Объясните, почему Base64 не является шифрованием. Сравните с Bearer-запросом из Postman. Отправка Basic в защищённое API стенда должна дать `401`, потому что этот API принимает Bearer.

## OAuth 2.0 Authorization Code с PKCE

Составьте последовательность: клиент создаёт `code_verifier` и `code_challenge`; браузер открывает endpoint авторизации с `state`; пользователь подтверждает доступ; сервер возвращает код на зарегистрированный redirect URI; клиент обменивает код с verifier на access token; ресурс получает Bearer-токен.

Проанализируйте готовые ответы обмена: успех `{"access_token":"учебный-токен","token_type":"Bearer","expires_in":3600}`; неверный verifier `{"error":"invalid_grant"}`; истёкший токен ресурса `401`; недостаточные права `403`. Найдите разницу между аутентификацией клиента, пользовательским входом и проверкой доступа к ресурсу. Это упражнение на контракт и последовательность, не работающий OAuth-провайдер.

## XML

Сопоставьте JSON `{"ticket":{"id":10,"title":"Учебная заявка"}}` и XML `<ticket><id>10</id><title>Учебная заявка</title></ticket>`. Укажите Content-Type, типы данных и правила экранирования `&` и `<`. Напишите проверку чтения title через стандартный XML-парсер на фиксированном учебном примере. Основное API принимает JSON; XML-запрос в POST создания не должен создать запись.
